# Bugs Found During Spec Creation

Bugs discovered by reading source code against spec rules. Each entry links to the spec that surfaced it.

| ID | Module | File | Description | Spec rule | Status |
|----|--------|------|-------------|-----------|--------|
| BUG-001 | session_init | `capture/session_init/workflow.py` | `create_session` does not validate `compound` against `VALID_COMPOUNDS` before the DB insert — any string reaches the DB silently | R-002 in `session-init.md` | open |
| BUG-002 | session_init | `capture/session_init/workflow.py` | `participant_id` is not validated as a UUID before the DB call — psycopg2 raises `InvalidTextRepresentation` with no helpful message when a non-UUID string is passed | R-003 in `session-init.md` | open |
| REFACTOR-001 | forwarder | `capture/forwarder/stream_thread/` | `StreamThread` was split across files by passing `self` to free functions (`stream_chunks.py`, `stream_db.py`, `stream_drift.py`, etc.) that reach directly into `_` private attributes. Breaks encapsulation without achieving real modularity. Should be restructured so each module either: (a) becomes real methods on the class, or (b) receives a purpose-built data object instead of the full `self`. Makes unit testing harder — tests must construct a `StreamThread` to call any of these functions. | forwarder.md R-012 – R-020 | refactor candidate |
| REFACTOR-002 | echo_handler | `capture/echo_handler/runtime.py` | `run_echo_thread` and `process_next_sample` receive `thread` (an `ECHOThread`) and access `thread._cfg`, `thread._xdf`, `thread._stop_event` directly — same encapsulation violation as REFACTOR-001, but lighter. `db.py` and `ECHOWriter` are correctly structured (take explicit params). Only `runtime.py` has the pattern. Fix: pass `_cfg`, `_xdf`, and `_stop_event` as explicit arguments rather than the whole thread object. | echo-handler.md R-016 – R-020 | refactor candidate |
| BUG-003 | watchdog | `capture/watchdog/db.py` | In `log_restart`, `psycopg2.connect()` (line 51) and `lookup_compound()` (line 52) are called OUTSIDE the `try/except Exception` block. A DB connection failure or a missing-session `RuntimeError` from `lookup_compound` propagates unhandled through `record_unexpected_exit` → `run_watchdog_loop`, crashing the entire watchdog process. Compare `mark_session_closing` and `mark_session_failed` which correctly put the `psycopg2.connect` call inside the `try`. Fix: wrap the entire body of `log_restart` (including `psycopg2.connect` and `lookup_compound`) in the `try/except` block. | watchdog.md R-009 | open |
